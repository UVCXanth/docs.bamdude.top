# Бібліотека Manyfold

[Manyfold](https://manyfold.app/) — це відкрита бібліотека 3D-моделей, яку розгортають на власному сервері. BamDude підключається до одного екземпляра Manyfold і показує його каталог на сторінці **Джерела моделей**: ви переглядаєте моделі й шукаєте серед них, відкриваєте модель, щоб побачити її файли, та імпортуєте потрібні до [файлового менеджера](file-manager.md). Далі їх нарізають, ставлять у чергу й друкують, як будь-який інший файл бібліотеки.

BamDude лише читає з Manyfold. Він нічого там не змінює, не завантажує туди й не видаляє.

---

## :material-cloud-download: Як це працює { #how-it-works }

```
Джерела моделей → вкладка Manyfold ─→ пошук / гортання моделей ─→ відкрити модель
        │
        └→ Імпортувати файл ─→ BamDude завантажує його з Manyfold ─→ файл у бібліотеці
```

| Крок | Що відбувається |
|------|-----------------|
| 1. Підключення | Адміністратор вводить адресу Manyfold, ідентифікатор клієнта й секрет застосунку Manyfold у **Налаштування → Мережа → Підключення Manyfold**. |
| 2. Перегляд | Вкладка **Manyfold** на сторінці **Джерела моделей** показує моделі, які власник цього застосунку бачить у Manyfold. Пошук і поділ на сторінки виконує Manyfold. |
| 3. Модель | Показано її зображення, автора, ліцензію, теги й файли, з позначкою на кожному файлі, який уже є в бібліотеці. |
| 4. Імпорт | Сервер BamDude завантажує файл із Manyfold, зберігає його в папку **Manyfold** бібліотеки (або в ту, яку ви вибрали) і записує, з якої моделі він походить. |

Усі, хто має право на Manyfold, бачать той самий каталог — той, який бачить власник застосунку. Підключення одне на всю інсталяцію, а не окреме для кожного користувача.

## :material-clipboard-check-outline: Вимоги { #requirements }

- **Manyfold 0.150 або новіший.** Екземпляр Manyfold не повідомляє свою версію, тому BamDude читає його власний опис API (`/api/v0/openapi.json`) і перевіряє, що в ньому є список моделей і завантаження самого файла. Екземпляр без них отримує відповідь *Цей Manyfold застарий. BamDude потрібен Manyfold 0.150 або новіший.*
- **Застосунок у Manyfold** з областями доступу `public` і `read`. BamDude входить з ідентифікатором клієнта й секретом цього застосунку.
- **Адреса, до якої дістається сервер BamDude.** Усі запити йдуть із сервера, на якому працює BamDude, тож до Manyfold має діставатися саме ця машина, а не ваш браузер.

## :material-connection: Підключення { #connecting }

### У Manyfold { #connecting-manyfold }

Ця частина — власний інтерфейс Manyfold.

1. Увійдіть у Manyfold як користувач, чиї моделі має показувати BamDude.
2. Відкрийте меню користувача → **API keys** і створіть застосунок.
3. Дайте йому області доступу `public` і `read`.
4. Скопіюйте його ідентифікатор клієнта (client ID) і секрет клієнта (client secret).

### У BamDude { #connecting-bamdude }

Відкрийте **Налаштування → Мережа**. Картка **Підключення Manyfold** містить усе підключення:

| Поле | Що вводити |
|------|------------|
| **Використовувати Manyfold** | Перемикач, який вмикає джерело. Увімкнути його можна лише тоді, коли є адреса, ідентифікатор клієнта й секрет клієнта. |
| **Адреса Manyfold** | Адреса екземпляра, що починається з `http://` або `https://` — наприклад `http://192.168.1.10:3214`. Шлях дозволено, якщо Manyfold розміщено за ним; імена користувачів, паролі, `?` і `#` — ні. |
| **Ідентифікатор клієнта** | Ідентифікатор клієнта застосунку. |
| **Секрет клієнта** | Секрет клієнта застосунку. Його можна лише записати: картка показує, чи секрет збережено, але ніколи не показує його значення. |

Далі:

1. Натисніть **Перевірити підключення**. Перевіряються значення, які зараз у формі, — збережені чи ні, — і нічого не зберігається.
2. Увімкніть **Використовувати Manyfold**.
3. Натисніть **Зберегти підключення**. Повідомлення *Підключення Manyfold збережено* це підтверджує.

Змінювати й перевіряти підключення може лише адміністратор. Усі інші, хто може читати налаштування, бачать картку лише для читання, з приміткою *Змінювати й перевіряти підключення до Manyfold може лише адміністратор.*

### Секрет клієнта { #client-secret }

Коли секрет збережено, поле пропонує три дії: **Залишити поточні облікові дані**, **Замінити облікові дані** та **Очистити облікові дані**.

Збережений секрет належить адресі та ідентифікатору клієнта, для яких його зберегли. Змініть будь-що з них — і картка знову попросить секрет: *Введіть секрет клієнта, щоб продовжити.* Сервер теж відмовиться зберігати чи перевіряти підключення зі старим секретом: *Адресу або ідентифікатор клієнта змінено: введіть секрет клієнта ще раз.* Так зроблено навмисно: секрет не можна надсилати на адресу, для якої його не вводили, а інший ідентифікатор клієнта — це інший застосунок.

### Що показує перевірка підключення { #test-connection }

Перевірка читає опис API екземпляра, входить і читає першу сторінку моделей.

| Результат | Що він означає |
|-----------|----------------|
| *Підключено. Моделей, які бачить BamDude: N* | Усе працює. N — це те, що бачить власник застосунку. |
| *Ця адреса не відповідає так, як Manyfold 0.150 або новіший.* | За адресою щось відповідає, але не описом API Manyfold. Перевірте адресу та порт. |
| *Цей Manyfold застарий. BamDude потрібен Manyfold 0.150 або новіший.* | Це Manyfold, але без завантаження файлів, потрібного BamDude. Оновіть Manyfold. |
| *Manyfold перенаправляє на https. Введіть його адресу з https://.* | Адресу введено з `http://`, а Manyfold відсилає на `https://`. BamDude за таким перенаправленням не йде; введіть адресу з `https://`. |
| *Manyfold не прийняв ідентифікатор клієнта або секрет.* | Ідентифікатор клієнта чи секрет хибні, або застосунок видалено. |
| *Застосунку Manyfold потрібна область доступу «read». Створіть застосунок з областями «public» і «read».* | Застосунок є, але без області `read`. |
| *Manyfold обмежує кількість запитів. Спробуйте за кілька хвилин.* | Manyfold обмежує, як часто застосунок може входити. Зачекайте кілька хвилин. |
| *BamDude не може звʼязатися з Manyfold. Перевірте адресу й чи працює Manyfold.* | Відповіді немає: хибна адреса, закритий порт, мережевий екран, сертифікат, якому сервер не довіряє, або Manyfold не працює. |
| *Manyfold відповів у формі, якої BamDude не розуміє. Можливо, його версія застара чи надто нова, або проксі перед ним змінює відповіді.* | Див. нижче про [стиснені відповіді](#network-rules) — зазвичай причина в проксі, що стискає. |

## :material-shield-lock-outline: Мережа й правила безпеки { #network-rules }

!!! info "Куди BamDude підключається, а куди ні"
    - **Адреса може бути у вашій власній мережі.** Працюють і `http://`, і `https://`, зокрема для приватної чи локальної (loopback) адреси — домашній сервер тут звичайний випадок.
    - **Для `https://` потрібен сертифікат, якому сервер BamDude вже довіряє.** Поля для власного сертифіката немає, а самопідписаний не приймається. Сервер довіряє тому самому набору сертифікатів, що й для інших своїх зʼєднань; `SSL_CERT_FILE` або `SSL_CERT_DIR` вказують йому інший.
    - **BamDude спілкується лише з налаштованою адресою.** Адреси, що трапляються у відповідях Manyfold, ніколи не запитуються, а дані входу надсилаються тільки на цю адресу. Проксі, заданий змінними середовища сервера, не використовується.
    - **Ваш браузер ніколи не звертається до Manyfold.** Зображення й файли отримує сервер BamDude і сам віддає їх браузеру. Єдине посилання, що веде за межі BamDude, — **Відкрити в Manyfold**, яке ви натискаєте самі.
    - **До адрес хмарних метаданих, link-local та інших спеціальних адрес BamDude не звертається ніколи**, хоч би що було введено і хоч би на що вказувало імʼя.

!!! info "Бібліотека на S3 чи іншому обʼєктному сховищі"
    Коли Manyfold тримає файли в обʼєктному сховищі, на запит завантаження він відповідає перенаправленням до цього сховища. BamDude йде за ним — до сховища в локальній мережі чи в інтернеті, через `http://` або `https://` (наприклад, MinIO поруч із Manyfold) — і забирає файл там без даних входу. Відмову отримують лише адреси, які ніколи не бувають сховищем файлів: адреси хмарних метаданих і link-local. Адреса сховища має бути досяжною із сервера BamDude, а не лише з Manyfold.

!!! warning "Зворотний проксі не повинен стискати відповіді"
    BamDude просить у Manyfold нестиснені відповіді, а стиснену відхиляє, не читаючи, — обмеження розміру рахуються за байтами, які надходять. Зворотний проксі перед Manyfold, який стискає попри це, призводить до того, що кожен запит завершується так:

    *Manyfold відповів у формі, якої BamDude не розуміє. Можливо, його версія застара чи надто нова, або проксі перед ним змінює відповіді.*

    Вимкніть на цьому проксі стиснення відповідей для запитів BamDude.

## :material-view-grid-outline: Перегляд { #browsing }

Пункт **Джерела моделей** у бічній панелі відкриває сторінку; на ній по одній вкладці на джерело — **MakerWorld** і **Manyfold**. Вкладку бачать користувачі з правом на це джерело, а смужка вкладок зʼявляється, коли вкладок у вас більше однієї. Вкладка Manyfold є, коли Manyfold підключено й увімкнено; до того її бачать лише користувачі, які можуть змінювати налаштування, з приміткою *Manyfold не підключено*.

| На вкладці | Що робить |
|------------|-----------|
| **Пошук моделей** + **Шукати** | Надсилає ваші слова у власний пошук Manyfold і показує першу сторінку результатів. На запит, якого Manyfold не може прочитати, відповідь така: *Manyfold не зрозумів цей пошуковий запит. Спробуйте звичайні слова.* |
| **Моделей: N** | Скільки моделей Manyfold повідомляє для поточного пошуку. |
| Плитки моделей | Зображення й назва кожної моделі. Натисніть плитку, щоб відкрити модель. Модель без зображення показано нейтральною плиткою. |
| **Попередня** / **Наступна** | Гортання сторінок. Розмір сторінки не належить BamDude: це налаштування власника застосунку в Manyfold, як і порядок моделей. |

Адреса сторінки містить пошукові слова, номер сторінки й відкриту модель. Посиланням на неї можна поділитися, перезавантаження повертає на те саме місце, а кнопка **Назад** у браузері повертає від моделі до списку, з якого її відкрили.

Зображення йдуть через BamDude: сервер отримує картинку з Manyfold і віддає її лише тоді, коли це справді зображення. Картинка — та, яку Manyfold показує для моделі: фото або рендер 3D-файла, якщо Manyfold його зробив; коли рендера немає, BamDude показує перший файл-зображення моделі. Модель без того й без іншого має нейтральну плитку; увімкнення рендерів моделей у налаштуваннях Manyfold дасть таким моделям картинку.

## :material-cube-outline: Модель { #a-model }

Відкрита модель показує своє зображення, назву, підпис, поля **Автор** і **Ліцензія**, теги та посилання **Відкрити в Manyfold** на сторінку моделі. **До списку моделей** повертає до списку.

Модель, яку Manyfold позначає як делікатну, має позначку **Делікатний вміст**, а її зображення лишається розмитим — *У Manyfold позначено як делікатний вміст. Натисніть, щоб показати.* — доки ви його не натиснете.

### Файли { #files }

У розділі **Файли** перелічено кожен файл моделі з назвою та, коли вони відомі, розміром і позначкою **з підтримками**, якщо Manyfold каже, що файл уже з підтримками.

| Файл | Що можна зробити |
|------|------------------|
| `.3mf`, `.stl`, `.step`, `.stp`, `.obj` | Можна імпортувати. |
| Будь-який інший тип (зображення, документи, архіви, інші формати) | Показано з позначкою *не імпортується: BamDude бере файли 3MF, STL, STEP і OBJ*. |
| Файл, який Manyfold показує у списку, але не дає застосунку завантажити | Показано з позначкою *Manyfold не віддає цей файл*. |
| Уже в бібліотеці | Позначено **У бібліотеці**, а **Показати в бібліотеці** відкриває його папку у файловому менеджері. |

**У бібліотеці** означає, що бібліотека містить файл, імпортований саме з цього файла цієї моделі, він не в кошику і вам дозволено його бачити.

Список файлів Manyfold не містить назв і розмірів, тож BamDude запитує їх файл за файлом, по двадцять за раз. У великій моделі решта має позначку *подробиці ще не завантажено*, а **Завантажити подробиці ще для частини файлів** отримує наступну порцію. Файл можна імпортувати й до того, як його подробиці завантажено.

## :material-import: Імпорт { #importing }

Для імпорту потрібні право на імпорт із Manyfold і право завантажувати файли до бібліотеки; без них модель показано без елементів імпорту.

| Що потрібно | Як |
|-------------|----|
| Один файл | **Імпортувати** в його рядку. |
| Кілька файлів моделі | Позначте їх (або **Вибрати все**), потім **Імпортувати вибрані (N)**. |
| Усі файли моделі | **Імпортувати все** — кожен придатний до імпорту файл, якого ще немає в бібліотеці. |
| Файли кількох моделей | У списку позначте моделі (або **Вибрати всі на сторінці**), потім **Імпортувати їхні файли**. Позначки зберігаються, поки ви гортаєте каталог; **Зняти вибір** їх прибирає. Імпортується кожен придатний до друку файл цих моделей, якого немає в бібліотеці. |

**Імпортувати до** вибирає місце призначення. Якщо лишити **Тека Manyfold**, файли потрапляють до папки `Manyfold` верхнього рівня бібліотеки, яка створюється під час першого імпорту. Зовнішня папка лише для читання місцем призначення бути не може.

### Як проходить імпорт { #import-run }

- Файли імпортуються **один за одним**. Файл, який не вдалося імпортувати, решту не зупиняє.
- **Один імпорт за раз.** Поки він триває, елементи імпорту вимкнено: *Триває імпорт. Дочекайтеся його завершення або скасуйте його.*
- **Імпорт триває, коли ви йдете з вкладки чи сторінки.** Він належить вкладці браузера, у якій відкрито BamDude, а не вкладці Manyfold: сповіщення — *Імпорт з Manyfold: 2/5* — супроводжує його по всьому BamDude, а ви тим часом користуєтеся рештою.
- **Скасувати імпорт** зупиняє перед наступним файлом. Файл, який саме імпортується, спершу доводиться до кінця: *Зупиняємо після файла, який зараз імпортується…*
- **Перезавантаження або закриття сторінки завершує імпорт.** Нічого не відновлюється. Після перезавантаження BamDude каже, як далеко він дійшов: *Сторінку перезавантажили під час імпорту: було опрацьовано 3 з 5 файлів. До решти черга не дійшла, а файл, який саме імпортувався, міг як потрапити до бібліотеки, так і ні — позначки «У бібліотеці» показують, що у вас є.*
- Відмова, яку не обійде жоден наступний файл, — Manyfold вимкнено чи відключено, облікові дані не прийнято, підключення змінилося, на сервері не лишилося місця — завершує імпорт одразу й каже, до скількох файлів черга не дійшла.

Коли імпорт завершено, на вкладці Manyfold лишається підсумок, доки ви його не закриєте, — *Імпортовано: 4 · уже в бібліотеці: 1 · не вдалося: 0* — з окремим рядком для кожного файла, який не вдалося імпортувати, і причиною. Сповіщення каже те саме, де б ви не були. **Імпортувати** для одного файла відповідає лише сповіщенням: *Імпортовано name.stl* або *Уже є у вашій бібліотеці*.

### Обмеження { #import-limits }

- **1 ГБ на файл.** Більший файл отримує відмову: *Файл більший за 1 ГБ.*
- **30 хвилин на завантаження.** Завантаження, яке триває довше, припиняється.
- **Два завантаження одночасно на інсталяцію**, для всіх користувачів разом. Файл, для якого обидва місця зайняті, чекає — вкладка показує *У черзі — зараз виконується імпортів: 2* або *Чекаємо на вільне місце для імпорту…* — і пробується знову; якщо місце так і не звільнилося, він завершується з *Зараз виконуються інші імпорти. Спробуйте ще раз за хвилину.*
- **Спершу перевіряється вільне місце.** До початку завантаження серверу потрібне місце для файла й запас: *На сервері не залишилося місця для цього файлу.*

Завантаження пишеться в папку `model-imports` каталогу даних BamDude і переноситься до бібліотеки, коли воно завершене. Незавершені завантаження видаляються, а те, що лишив там зупинений сервер, прибирається під час наступного запуску. Ця папка не входить до резервної копії.

### Що потрапляє до бібліотеки { #import-result }

| | |
|---|---|
| **Назва** | Власна назва файла в Manyfold. Якщо бібліотека не може прийняти цю назву, файл зберігається як `manyfold-<ідентифікатор файла>` зі своїм розширенням. |
| **Без повторного завантаження** | Файл, імпортований раніше, не завантажується знову — імпорт відповідає файлом бібліотеки, який його містить, і рахує його як *уже в бібліотеці*. Файл, точний вміст якого бібліотека вже має, теж не додається вдруге. |
| **Мініатюра** | STL чи OBJ отримує відрендерену бібліотекою картинку, як і завантажений вручну. Файл STEP автоматично її не отримує — скористайтеся **Згенерувати мініатюру** в його меню, див. [Мініатюри STEP](file-manager.md#step-thumbnails). |
| **Походження** | Файл зберігає адресу сторінки своєї моделі як **Джерело**, а також назву моделі, автора й ліцензію — такими, якими вони були під час імпорту. Їх показано в діалозі [Деталі файла](file-manager.md#file-details); **Відкрити в Manyfold** у меню файла відкриває сторінку моделі. |

## :material-shield-key: Права { #permissions }

| Право | Що дає |
|-------|--------|
| `manyfold:view` | Відкривати вкладку Manyfold, шукати й гортати каталог, відкривати моделі, бачити зображення. |
| `manyfold:import` | Імпортувати файли до бібліотеки. Для імпорту потрібне ще й `library:upload`, бо він додає файл до бібліотеки. |

Типові групи дають обидва права групам **Administrators** і **Operators**, а `manyfold:view` — групі **Viewers**. На наявній інсталяції кожна група, що має `makerworld:view`, отримує `manyfold:view`, а кожна група, що має `makerworld:import`, — `manyfold:import`; Administrators отримують обидва.

Підключення Manyfold до цих прав не належить: щоб зберегти чи перевірити підключення, потрібен **адміністратор** із правом `settings:update`. Щоб прочитати підключення — адресу, ідентифікатор клієнта й те, чи збережено секрет, — потрібне `settings:read`.

Для [API-ключів](api-keys.md) `manyfold:view` належить до області **Can read status**, а `manyfold:import` — до **Manage Library**.

## :material-alert-circle-outline: Повідомлення і що робити { #troubleshooting }

| Повідомлення | Що воно означає | Що робити |
|--------------|-----------------|-----------|
| *Manyfold не підключено.* | Адресу, ідентифікатор клієнта чи секрет не збережено. | Адміністратор налаштовує підключення в **Налаштування → Мережа**. |
| *Manyfold вимкнено в налаштуваннях.* | Підключення збережено, але **Використовувати Manyfold** вимкнено. | Увімкніть і збережіть. |
| *Manyfold не прийняв ідентифікатор клієнта або секрет.* | Manyfold відмовляє у вході. | Перевірте застосунок у Manyfold; введіть його ідентифікатор і секрет ще раз. |
| *Застосунку Manyfold потрібна область доступу «read». Створіть застосунок з областями «public» і «read».* | Застосунку бракує області доступу. | Створіть застосунок з обома областями й підключіться з ним. |
| *Manyfold обмежує кількість запитів. Спробуйте за кілька хвилин.* | Власне обмеження запитів Manyfold. | Зачекайте кілька хвилин. |
| *BamDude не може звʼязатися з Manyfold. Перевірте адресу й чи працює Manyfold.* | Немає відповіді вчасно або немає зʼєднання взагалі. | Перевірте із сервера BamDude: адресу, порт, мережевий екран, сертифікат. |
| *Manyfold перенаправляє на https. Введіть його адресу з https://.* | Збережена адреса з `http://`, а Manyfold вимагає `https://`. | Збережіть адресу з `https://`. |
| *Цей Manyfold застарий. BamDude потрібен Manyfold 0.150 або новіший.* | В екземплярі немає завантаження файлів, яким користується BamDude. | Оновіть Manyfold. |
| *Ця адреса не відповідає так, як Manyfold 0.150 або новіший.* | За адресою не Manyfold, або замість нього відповідає проксі. | Перевірте адресу. |
| *Manyfold відповів у формі, якої BamDude не розуміє. Можливо, його версія застара чи надто нова, або проксі перед ним змінює відповіді.* | Відповідь, яку BamDude не може прочитати, — найчастіше через проксі, що її стискає. | Вимкніть на проксі стиснення для BamDude; див. [Мережа й правила безпеки](#network-rules). |
| *Manyfold не показав цього. Можливо, власник застосунку не має до цього доступу.* | Manyfold надіслав перенаправлення замість відповіді, як він робить для того, чого його користувач бачити не може. | Перевірте доступ власника застосунку в Manyfold. |
| *Manyfold не знаходить цієї моделі чи файла, або власник застосунку їх не бачить.* | Моделі чи файла вже немає, або їх приховано від цього користувача. | Перезавантажте список; перевірте в Manyfold. |
| *Сховище файлів, до якого перенаправив Manyfold, має адресу, з якою BamDude не з’єднується.* | Manyfold перенаправив завантаження на адресу хмарних метаданих чи link-local, на адресу з іменем користувача в ній або перенаправляв забагато разів. | Перевірте, де налаштовано сховище Manyfold; див. [Мережа й правила безпеки](#network-rules). |
| *BamDude не може звʼязатися зі сховищем файлів, до якого перенаправив Manyfold. Адреса сховища має бути досяжною із сервера BamDude, а не лише з Manyfold.* | Адресу сховища в Manyfold може відкрити лише сам Manyfold — наприклад, імʼя сервісу Docker на кшталт `http://minio:9000`. | Задайте в Manyfold таку адресу сховища, яку може відкрити й сервер BamDude. |
| *Сховище файлів за Manyfold відмовило в завантаженні.* | Сховище відповіло на завантаження помилкою. | Спробуйте ще раз; перевірте сховище за Manyfold. |
| *Імпортувати можна лише файли 3MF, STL, STEP і OBJ.* | Файл іншого типу. | — |
| *Файл більший за 1 ГБ.* | Перевищено обмеження розміру. | Завантажте його в Manyfold і додайте до файлового менеджера вручну. |
| *Зараз виконуються інші імпорти. Спробуйте ще раз за хвилину.* | Обидва місця для завантаження в інсталяції лишалися зайнятими. | Спробуйте, коли інші імпорти завершаться. |
| *На сервері не залишилося місця для цього файлу.* | Диск каталогу даних BamDude заповнений. | Звільніть місце на сервері. |
| *Підключення Manyfold змінилося під час імпорту. Спробуйте ще раз.* | Підключення змінили або вимкнули, поки файл завантажувався; цей файл не збережено. | Запустіть імпорт знову. |
| *Перевірка безпеки підключення до Manyfold не пройшла. Manyfold вимкнено до перезапуску BamDude.* | BamDude не зміг довести, що його зʼєднання йдуть лише на перевірені ним адреси, тому не користується жодним. Вкладка показує *Manyfold недоступний*. | Перезапустіть BamDude. Якщо повідомлення повертається, перевстановіть пакети Python BamDude з `requirements.txt`. |
| *BamDude не відповів. Перевірте зʼєднання і спробуйте ще раз.* | Браузер не отримав відповіді від самого BamDude. | Перевірте зʼєднання між браузером і BamDude. |

API Manyfold має версію `v0`: Manyfold може змінити його в наступному випуску, і зміна, якої BamDude не знає, проявиться одним із повідомлень вище.

## :material-minus-circle-outline: Чого немає { #not-there }

- **Немає вкладки з історією імпорту.** На відміну від MakerWorld, вкладка Manyfold історії не має; імпортоване позначено **У бібліотеці** на моделі й лежить у файловому менеджері.
- **У Manyfold нічого не записується.** Жодних завантажень туди, змін чи видалень, і про друк туди не повідомляється.
- **Одне підключення на інсталяцію.** Один екземпляр Manyfold, один застосунок; кожен користувач бачить те, що бачить власник цього застосунку.
- **Без вставлених посилань.** Адресу Manyfold, вставлену на вкладці MakerWorld, не розпізнано — Manyfold переглядають, а не вставляють.

## :material-file-code: Довідка для розробників { #developer-reference }

| Endpoint | Метод | Доступ | Призначення |
|---|---|---|---|
| `/api/v1/model-sources/manyfold/status` | GET | `manyfold:view` | `configured`, `usable`, адреса екземпляра `base_url` та `imports` — завантаження, що тривають, що чекають, і обмеження. |
| `/api/v1/model-sources/manyfold/models` | GET | `manyfold:view` | Одна сторінка моделей — така, якою її нарізав Manyfold. Параметри: `q` (до 200 символів), `page`. |
| `/api/v1/model-sources/manyfold/models/{model_id}` | GET | `manyfold:view` | Модель з усіма файлами та `already_imported` — файлами бібліотеки, які їх містять. `files_page` вибирає, яку порцію подробиць файлів читати. |
| `/api/v1/model-sources/manyfold/models/{model_id}/preview` | GET | медіа-токен, `manyfold:view` | Зображення моделі. Токен передається в `?token=`, бо `<img src>` не може надсилати заголовки. |
| `/api/v1/model-sources/manyfold/import` | POST | `manyfold:import` + `library:upload` | Імпорт одного файла: `model_id`, `file_id`, необовʼязковий `folder_id`. Відповідь: `library_file_id`, `filename`, `folder_id`, `was_existing`. |
| `/api/v1/model-sources/manyfold/connection` | GET | `settings:read` | Підключення: `enabled`, `url`, `client_id`, `client_secret_configured`. Сам секрет — ніколи. |
| `/api/v1/model-sources/manyfold/connection` | PUT | адміністратор + `settings:update` | Зберегти підключення. |
| `/api/v1/model-sources/manyfold/connection/test` | POST | адміністратор + `settings:update` | Перевірити чернетку підключення, нічого не зберігаючи. |

Відмова містить код `error` і текст `message`; статус — `400`, `404`, `409`, `413`, `502`, `503` або `507`. На відмову Manyfold ніколи не відповідають `401` чи `403` — ці статуси стосуються сеансу BamDude.
